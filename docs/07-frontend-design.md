# 가족 생활기록 시스템 — 프론트엔드 설계 (v1)

> 기준: 기능명세 v4, API명세 v1, 인증설계 v1
> 스택: **React Native + Expo / TypeScript**, 웹은 react-native-web
> 전략: **로직 공유 + UI 표현 분기** (앱 우선, 웹 따라오기)

---

## 0. 기술 스택

| 영역 | 선택 | 비고 |
|------|------|------|
| 프레임워크 | React Native + **Expo** | 기존 React 19 경험 활용 |

## 1. 정보 구조 / 네비게이션

### 1-1. 인증 분기
```
앱 시작 → 토큰 확인
  ├─ 없음/만료 → [로그인 스택]
  └─ 유효 → [메인 앱]
```

### 1-2. 메인 네비게이션 (플랫폼별 표현 분기)
- **모바일**: 하단 탭 바 (5 탭)
- **웹**: 좌측 사이드바 (동일 5 섹션)

```
[일정]  [가계부]  [기록]  [홈/타임라인]  [더보기]
```

> 2026-07 리뉴얼에서 사용빈도 기준으로 재배열(원래 [홈/타임라인] [가계부] [일정] [기록] [더보기] 순). 통합 타임라인은 여전히 날짜축 통합이라는 핵심 차별점 화면이지만, 탭 순서는 실사용 빈도를 우선했다 — 화면 자체의 중요도가 낮아진 것은 아님.

| 탭 | 핵심 화면 |
|----|-----------|
| 일정 | 캘린더(기본)·인라인 목록, 일정 상세, 전체기간 검색 |
| 가계부 | 거래 목록·통계, 계좌, 카테고리 |
| 기록 | 캘린더(기본)·인라인 피드, 기록 상세(읽기전용→수정), 전체기간 검색 |
| 홈/타임라인 | 통합 타임라인(날짜축), 빠른 입력 진입 |
| 더보기 | 이벤트 묶음, 가족·구성원, 외부연동, 개인 설정, 비밀번호 변경 |

## 3. 코드 공유 구조 (로직 공유 + UI 분기)

### 3-1. 디렉토리 (모노레포 또는 단일 Expo 프로젝트)
```
/src
  /api          ← 공유: axios 클라이언트, 엔드포인트별 훅(useTransactions 등)
  /domain       ← 공유: 타입(Transaction, Schedule...), 권한·통화·날짜 유틸
  /store        ← 공유: Zustand (auth, ui)
  /hooks        ← 공유: TanStack Query 훅, 비즈니스 로직
  /components   ← 분기: .tsx(공통) / .native.tsx / .web.tsx (필요시)
  /screens      ← 대부분 공유, 레이아웃만 플랫폼 분기
  /navigation   ← 분기: 모바일 탭바 / 웹 사이드바
  /theme        ← 공유: 토큰(색·간격·타이포)
```

### 3-2. 공유 vs 분기 기준
| 영역 | 공유율 | 비고 |
|------|--------|------|
| API·도메인·상태·훅 | ~100% | 플랫폼 무관 |
| 폼 로직·검증 | ~100% | Zod 스키마 공유 |
| 화면 구성 로직 | ~80% | 데이터 흐름 공유 |
| 레이아웃·네비게이션 | 분기 | 탭바 vs 사이드바 |
| 네이티브 기능 | 분기 | 카메라·사진·시큐어스토어 |

### 3-3. 플랫폼 분기 방법
- 파일 확장자: `Component.native.tsx` / `Component.web.tsx`
- `Platform.OS` 런타임 분기 (간단한 경우)
- 네이티브 전용 모듈은 web에서 no-op 또는 대체 구현

## 4. 핵심 UX 흐름

### 4-1. 빠른 입력 (MVP: 앱 내 버튼 / 위젯은 차기)
- **MVP**: 홈 화면 FAB(플로팅 버튼) → 빠른입력 화면. 위젯 없이 시작
  - 이유: Expo 관리형에서 위젯은 네이티브 모듈(prebuild/config plugin) 필요 → RN 첫 도전에 함정
- **차기(텔레그램 단계 이후)**: iOS WidgetKit/Android 위젯 탭 → 빠른입력 딥링크
- 빠른입력: 금액·메모·계좌·visibility(기본 개인) 최소 입력 → 저장

### 4-2. 사진 업로드 (3단계)
```
선택 → POST /photos/presign (storageKey 수신)
     → 바이너리 업로드
     → POST /photos/{id}/complete
```
- 진행률 표시, 실패 재시도, photoHash 중복 시 기존 사용

### 4-3. visibility 입력 UX
- 거래: 개인/부모공유 토글 (기본 개인)
- 일정·기록: 4단계 선택 (순수개인/공유개인/부모공유/가족공동)
- 공유개인 선택 시 subject 지정 UI

### 4-3-1. 빈 상태·마스킹 컴포넌트 규칙 (디자인 단계 필수)
백엔드가 마스킹/삭제 데이터를 내려주므로, 컴포넌트가 이 variant를 처음부터 가져야 나중에 안 갈아엎음:
- **마스킹된 계좌**(타인 공유거래, sourceAccount=null): "비공개" 회색 칩으로 표시(빈칸 금지)
- **삭제된 계좌·카테고리**(과거 거래 참조): "(삭제됨)" 접미사 + 흐린 색. 신규 입력 선택지엔 미노출
- **SHARED_PERSONAL SUMMARY 일정**: 일정 카드 컴포넌트는 **FULL/SUMMARY 2-variant** 필수.
  SUMMARY는 title 마스킹("바쁨")·시간만 표시. 같은 카드가 뷰어 PersonSetting에 따라 분기
- 공통: 빈 목록(거래·일정·기록 0건) 플레이스홀더 일관 컴포넌트

### 4-4. 토큰 갱신 (axios 인터셉터)
- 401 응답 → refresh 시도 → 성공 시 원요청 재시도, 실패 시 로그인 이동
- 동시 401 다중요청은 refresh 1회로 큐잉

### 4-5. 사이드패널 입력 (2026-07 리뉴얼 추가)
- 거래 입력(`/transaction/new`, `/transaction/[id]`)과 일정 등록(`/schedule/new`, `/schedule/[id]`)은 목록 화면을 가리지 않는 **우측 슬라이드 사이드패널**(`components/ui/SidePanel.tsx`)로 연다.
- Expo Router 구현: 해당 Stack.Screen을 `presentation:'transparentModal', animation:'slide_from_right', headerShown:false`로 등록 → 배경 목록이 유지된 채 오른쪽에서 폼이 슬라이드인.
- 기록(diary)은 폼 자체가 사진 업로드 등으로 커서 사이드패널 대신 기존 풀스크린 전환 유지.

### 4-6. 기록 작성 프로세스 — 묶음(Collection) 기반 연결 (2026-07 리뉴얼 추가)
가계부·일정·기록을 날짜 기준 묶음으로 엮는 흐름:
1. **일정 작성 화면**에서 묶음을 생성(이름 + 태그, 날짜는 그 일정의 시작~종료로 기본 제안). 묶음 생성은 항상 일정 화면이 기준점 — 가계부·기록 화면에는 "새 묶음" 버튼이 없다.
2. **가계부 인라인** 목록에서 상단 "선택" 버튼으로 다중선택 모드 진입 → 여러 거래 체크 → 하단 액션바의 `ComboBox`(이름·태그 검색)로 기존 묶음에 일괄 연결(`POST /transactions/link-collection`).
3. **기록 작성**에서 `CollectionPicker`(검색형 ComboBox)로 기존 묶음을 선택해 연결.
4. **기록 화면**은 일정에서 만든 묶음을 그 기간(startedAt~endedAt) 동안 매일 플레이스홀더 카드로 노출(그 날짜에 실제 기록이 없어도) — 클릭하면 **묶음 요약 화면**(연결된 거래+기록 통합 뷰)으로 이동.
5. 묶음 요약 화면에서 "수정" 없이도 연결된 거래 목록(메모 포함)·기록 본문을 바로 확인할 수 있고, 상단 "+ 거래/+ 일정/+ 기록" 퀵액션으로 collectionId가 미리 채워진 작성 화면에 진입해 계속 채워 나갈 수 있다.
- **태그**는 Schedule이 아니라 **Collection에만** 존재(`collection_tag`, 기존 `tag` 도메인 재사용) — 목적은 비슷한 이벤트를 태그로 재검색해 묶음을 재사용하기 위함(같은 태그의 묶음이 여러 날짜에 걸쳐 재사용될 수 있음, 날짜 종속 아님).

### 4-7. 인라인/캘린더 뷰 모드 + 정렬 + 캘린더 스팬 막대 (2026-07 리뉴얼 추가)
- 가계부·일정·기록 3개 화면 모두 `MonthNav` 우측에 소형 아이콘 토글 2개: `ViewModeToggle`(인라인↔캘린더, 기본 캘린더 — PersonSetting의 화면별 기본값으로 최초 로드 시 세팅, 화면 내 전환은 세션 로컬)과, 인라인 모드일 때만 노출되는 `SortOrderToggle`(asc/desc, 화면 로컬 상태 — 서버 저장 안 함).
- 캘린더(`MonthGrid`)는 주(week) 단위로 렌더링: 시작일~종료일이 있는 항목(종일 다일 일정, 묶음 기간)은 그 주의 날짜 칸에 걸쳐 이어지는 **막대(bar)**로 표시(구글 캘린더식, 겹치는 항목은 그리디 lane 배정으로 최대 2줄까지), 하루짜리 항목은 기존처럼 점(dot)으로 표시.
- 날짜 선택 시 그 날짜의 항목만, 선택 해제 시 해당 월 전체 항목을 보여준다(공통 규칙).

### 4-8. 전체기간 검색 (2026-07 리뉴얼 추가)
- 일정·기록 화면 헤더에 "검색" 진입점 → 바텀시트(`components/ui/SearchSheet.tsx`)에서 입력 300ms 디바운스 후 서버 검색(`GET /schedules?q=`, `GET /diaries?q=`, from/to 없이 호출해 **전체 기간** 대상).
- 일정: 제목·설명·장소 부분일치. 기록: 제목·본문·연결된 태그명 부분일치.
- 결과는 목록(목차) 형태로 노출. 항목 선택 시 폼/상세로 바로 이동하지 않고, **캘린더가 그 날짜로 이동**(월 전환 + 날짜 선택, 캘린더 모드가 아니면 캘린더 모드로 전환) — 이후 사용자가 이어서 상세를 열어보는 흐름.
